# Протокол Aegis Messenger

## Обзор

Aegis Protocol - это бинарный протокол прикладного уровня для высокопроизводительных систем обмена сообщениями с поддержкой шифрования, аутентификации и надежной доставки.

## Ключевые характеристики

- **Бинарный формат**: Минимальные накладные расходы на передачу
- **Шифрование**: AES-256-GCM для конфиденциальности
- **Аутентификация**: HMAC-SHA256 для целостности
- **Порядок сообщений**: Монотонные sequence numbers
- **Расширяемость**: Поддержка новых типов сообщений
- **Кроссплатформенность**: Big-endian порядок байтов

## Поля протокола

### Magic (4 байта)

- **Значение**: `0xAE6C5D7` (1869254311 в десятичной системе)
- **Назначение**: Идентификация протокола Aegis
- **Валидация**: Сообщения с другим magic отвергаются

### Version Major (1 байт)

- **Текущее значение**: `1`
- **Назначение**: Старшая версия протокола
- **Совместимость**: Изменение при несовместимых изменениях

### Version Minor (1 байт)

- **Текущее значение**: `0`
- **Назначение**: Младшая версия протокола
- **Совместимость**: Изменение при добавлении новых фич

### Flags (1 байт)

- **Текущее значение**: `0x00`
- **Назначение**: Флаги сообщения (зарезервировано)
- **Биты**:
  - Bit 0: Compressed payload (зарезервировано)
  - Bit 1: Encrypted payload (зарезервировано)
  - Bits 2-7: Зарезервировано для будущего

### Message Type (2 байта)

- **Порядок байтов**: Big-endian
- **Назначение**: Тип сообщения для маршрутизации
- **Значения**: См. таблицу типов сообщений

### Sequence ID (8 байт)

- **Порядок байтов**: Big-endian
- **Назначение**: Уникальный номер последовательности
- **Генерация**: Монотонно увеличивается для каждого соединения
- **Обнаружение потерь**: Пропуски в sequence numbers

### Payload Length (4 байта)

- **Порядок байтов**: Big-endian
- **Максимальное значение**: 1,048,064 (1MB - заголовок - MAC)
- **Назначение**: Длина полезной нагрузки в байтах

### Payload (переменная длина)

- **Формат**: Зависит от типа сообщения
- **Шифрование**: Может быть зашифрован AES-GCM
- **Сжатие**: Может быть сжат (зарезервировано)

### MAC (32 байта)

- **Алгоритм**: HMAC-SHA256
- **Ключ**: Отдельный MAC ключ из HKDF
- **Покрытие**: Все поля сообщения, включая MAC (кроме самого MAC)
- **Проверка**: Перед обработкой любого сообщения

## Типы сообщений

| ID | Тип | Описание | Payload |
|----|------|-----------|----------|
| 0 | Unknown | Недопустимый тип | N/A |
| 1 | Auth | Аутентификация | AuthData |
| 2 | Ping | Keep-alive | PingData |
| 3 | Message | Сообщение чата | MessageData |
| 4 | Ack | Подтверждение | AckData |
| 5 | Error | Ошибка | ErrorData |
| 6 | Handshake | Рукопожатие | HandshakeData |

## Детальные форматы payload

### Auth (ID: 1)

```
+------------------+
| Auth Token (var) |
+------------------+
```

- **Auth Token**: JWT или токен аутентификации

### Ping (ID: 2)

```
+------------------+
| Timestamp (8)    |
+------------------+
```

- **Timestamp**: Unix timestamp в миллисекундах

### Message (ID: 3)

```
+------------------+------------------+
| From ID (8)     | To ID (8)        |
+------------------+------------------+
| Message Type (1) | Reserved (3)     |
+------------------+------------------+
| Message Text (var)                    |
+--------------------------------------+
```

- **From ID**: ID отправителя
- **To ID**: ID получателя (0 для broadcast)
- **Message Type**: 0=text, 1=image, 2=file
- **Message Text**: Содержимое сообщения

### Ack (ID: 4)

```
+------------------+------------------+
| Original Seq (8) | Status (1)       |
+------------------+------------------+
| Reserved (3)     |
+------------------+
```

- **Original Seq**: Sequence ID подтверждаемого сообщения
- **Status**: 0=OK, 1=Error, 2=Retry

### Error (ID: 5)

```
+------------------+------------------+
| Error Code (2)   | Reserved (2)     |
+------------------+------------------+
| Error Message (var)                   |
+--------------------------------------+
```

- **Error Code**: Код ошибки
- **Error Message**: Текст ошибки

### Handshake (ID: 6)

```
+------------------+------------------+
| Client Version (4)| Nonce (12)       |
+------------------+------------------+
| Public Key (var)                     |
+--------------------------------------+
```

- **Client Version**: Версия клиента
- **Nonce**: Случайные данные для ключевого обмена
- **Public Key**: Публичный ключ клиента

## Процесс установления соединения

### 1. TCP Connection

```
Client                    Server
   |                        |
   | TCP SYN               |
   |--------------------->   |
   | TCP SYN+ACK           |
   |<---------------------|
   | TCP ACK               |
   |--------------------->   |
   |                        |
```

### 2. Protocol Handshake

```
Client                    Server
   |                        |
   | Handshake (v1.0)      |
   |--------------------->   |
   | Validate Magic/Version |
   | Generate Server Nonce  |
   | Derive Session Keys   |
   |                        |
   | Handshake Response     |
   |<---------------------|
   | Validate Server MAC   |
   | Connection Ready      |
   |                        |
```

### 3. Authentication

```
Client                    Server
   |                        |
   | Auth Message           |
   |--------------------->   |
   | Validate Token        |
   |                        |
   | Auth Response (ACK)   |
   |<---------------------|
   | Authenticated         |
   |                        |
```

## Управление ключами

### Иерархия ключей

```
Master Key (долгосрочный)
    |
    v
HKDF Derivation
    |
    +-- Encryption Key (сессионный)
    |
    +-- MAC Key (сессионный)
    |
    +-- Salt (постоянный)
```

### Процесс вывода ключей

1. **Master Key**: Долгосрочный ключ сервера
2. **HKDF**: Rfc5869DeriveBytes с salt="AegisKeyDerivation"
3. **Session Keys**: Уникальные для каждого соединения
4. **Rotation**: Периодическая смена ключей

### Безопасность ключей

- **Zero Memory**: CryptographicOperations.ZeroMemory()
- **Secure Storage**: Защищенное хранилище ключей
- **Key Separation**: Раздельные ключи для шифрования и MAC

## Обработка ошибок

### Протоколные ошибки

- **Invalid Magic**: `0x0001`
- **Version Mismatch**: `0x0002`
- **Message Too Large**: `0x0003`
- **Invalid MAC**: `0x0004`

### Прикладные ошибки

- **Authentication Failed**: `0x1001`
- **Message Rejected**: `0x1002`
- **Rate Limited**: `0x1003`
- **Internal Error**: `0x1999`

### Восстановление после ошибок

1. **Protocol Errors**: Немедленное закрытие соединения
2. **Application Errors**: Error сообщение с кодом
3. **Network Errors**: Повторные попытки с экспоненциальным backoff

## Производительность

### Оптимизации

- **Zero Copy**: Использование Span<T> без аллокаций
- **Batch Processing**: Групповая обработка сообщений
- **Connection Pooling**: Переиспользование соединений
- **Async I/O**: Неблокирующие операции

### Метрики

- **Latency**: < 1ms для локальной сети
- **Throughput**: > 100,000 msg/sec на ядро
- **Memory**: < 1KB на соединение
- **CPU**: < 5% на 10,000 соединений

## Совместимость

### Версионирование

- **Major**: Несовместимые изменения
- **Minor**: Обратная совместимость

### Обратная совместимость

- **Старые клиенты**: Работают с новым сервером
- **Новые клиенты**: Могут требовать новый сервер
- **Флаги**: Зарезервированы для будущего

## Реализация

### Рекомендации

1. **Валидация**: Всегда проверяйте magic и MAC
2. **Порядок байтов**: Используйте big-endian
3. **Буферы**: Используйте ArrayPool для производительности
4. **Асинхронность**: Все I/O операции должны быть async
5. **Логирование**: Детально логируйте ошибки протокола

### Тестирование

- **Unit Tests**: Для каждого компонента протокола
- **Integration Tests**: Для полного цикла сообщений
- **Load Tests**: Для производительности
- **Security Tests**: Для криптографии

## Безопасность

### Угрозы и защита

- **Man-in-the-Middle**: Защита через MAC
- **Replay Attacks**: Защита через sequence numbers
- **Eavesdropping**: Защита через AES-GCM
- **Key Compromise**: Защита через rotation

### Best Practices

- **Perfect Forward Secrecy**: Регулярная смена ключей
- **Random Nonces**: Криптографически случайные nonce
- **Constant Time**: Сравнение MAC в постоянное время
- **Memory Safety**: Безопасная очистка памяти

## Расширения

### Новые типы сообщений

- **Range**: 7-65535 зарезервированы
- **Registration**: Требует документации формата
- **Backward Compatibility**: Старые клиенты игнорируют неизвестные типы

### Новые флаги

- **Bits 0-1**: Зарезервированы для сжатия/шифрования
- **Bits 2-7**: Доступны для расширений
